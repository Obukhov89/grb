## Запуск в dev-среде

### 1.1. Проверка наличия Docker

Откройте терминал и выполните:

```sh
docker --version
```

Если увидите версию Docker, переходите к следующему шагу. Если команда не найдена — установите Docker:

- Windows: [Docker Desktop](https://docs.docker.com/desktop/install/windows-install/)
- macOS: [Docker Desktop](https://docs.docker.com/desktop/install/mac-install/)
- Linux: [Docker](https://docs.docker.com/engine/install/)

### 1.2 Проверка наличия Docker Compose

```sh
docker compose version
```

Если команда не найдена, установите Docker Compose согласно [официальной документации](https://docs.docker.com/compose/install/).

### 1.3 Запуск Traefik

Traefik используется как прокси для локальных доменов, чтобы была возможность всегда получить доступ к приложению по удобному адресу (например, ic.dev.local).

Используйте репозиторий: https://github.com/humblera1/traefik-local.

#### 1.3.1 Клонируйте репозиторий Traefik

```sh
git clone https://github.com/humblera1/traefik-local.git
cd traefik-local
```

#### 1.3.2 Запустите Traefik

Traefik и ваши приложения должны находиться в одной docker-сети. Сначала создайте внешнюю сеть:

```sh
docker network create traefik_net
```

Убедитесь, что файл `docker-compose.yml` находится в корне проекта. Запустите Traefik:

```sh
docker compose up -d
```

Traefik будет слушать порты 80 и 443 на вашей машине.

#### 1.3.3 Добавьте локальный домен в hosts

Откройте файл hosts с правами администратора:

- Windows: `C:\Windows\System32\drivers\etc\hosts`
- Linux/macOS: `/etc/hosts`

Добавьте строку:

```
127.0.0.1   ic.dev.local
```

Сохраните файл.

#### Troubleshooting

Более подробную инструкцию по запуску и отлову ошибок можно найти в README репозитория с traefik.

### 1.4 Клонирование репозитория приложения

```sh
git clone http://git.dev.ulab.space/ulab-new/ic.git
cd ic
```

### 1.5 Настройка файла .env

Скопируйте пример файла:

```sh
cp .env.example .env
```
Откройте .env в любом редакторе и заполните переменные:
- Пароли и логины к базе данных
- Лицензионный ключ Bitrix (`BITRIX_LICENSE_KEY`)
- Прочие параметры, необходимые для работы приложения

**Важно**: Не публикуйте свой .env в общий доступ!

### 1.6 Запуск приложения

Перейдите в папку проекта:

```sh
cd ic
```

Контейнер с приложением запускается на основе базового образа, который хранится Docker Hub и содержит все необходимые зависимости для работы приложения.
Поэтому предварительно необходимо авторизоваться в Docker Hub:

```sh
docker login -u maximniistrom
```

Пароль можно получить у команды разработчиков, ответственных за проект.

Запустите контейнеры:

```sh
docker compose -f docker-compose.dev.yaml up -d
```

Первый запуск может занять достаточно много времени: скачивается образ с ядром битрикс, копируется локальная структура, устанавливаются зависимости.

### 1.7 Дамп

Для того чтобы начать работу, необходимо импортировать дамп в контейнер с базой данных. Для этого получите файл дампа, например `dump.sql`.

Дамп можно скопировать в контейнер с помощью команды:

```sh
docker compose -f docker-compose.dev.yaml cp dump.sql mysql:/tmp
```

После этого подключитесь к контейнеру и импортируйте файл любым удобным способом, например, через `source`:

```sh
docker compose -f docker-compose.dev.yaml exec -it mysql sh

# В контейнере
mysql -u ic_user -p

# В оболочке mysql:
use ic_base;
source /tmp/dump.sql;
```

## Структура проекта

Данный проект использует Docker Compose для организации среды разработки на основе контейнеров.

Проект состоит из четырех основных контейнеров:

### 1. `app` — PHP + Apache и Nginx

- **Назначение:** Основной контейнер приложения, в котором работает связка PHP, Apache и Nginx.
- **Особенности:**
    - Используется кастомный базовый образ, включающий ядро Битрикс, необходимые PHP-модули, Apache, Nginx, Cron и Supervisor.
    - Такой подход позволяет избежать монтирования большого каталога с ядром Битрикс на хост-машину.
    - Контейнер подключен к нескольким сетям для взаимодействия с базой данных и push-сервером.
    - Для хранения загрузок и документов предусмотрены именованные Docker-тома (именованный том `upload` для загрузок и `./protocol_generator` на хосте).

### 2. `mysql` — СУБД MySQL

- **Назначение:** Контейнер с базой данных MySQL.
- **Особенности:**
    - Использует официальный образ MySQL (версия 5.7.33).
    - Все данные хранятся в отдельном Docker-томе для сохранности между перезапусками.
    - В dev-среде порт базы данных пробрасывается наружу для подключения с хоста.
    - Контейнер объединён в одну сеть с `app` для безопасного взаимодействия.

### 3. `redis` — Кэш и Pub/Sub

- **Назначение:** Контейнер с Redis для кеширования и поддержки push-уведомлений.
- **Особенности:**
    - Использует официальный образ Redis.
    - Данные Redis сохраняются в отдельном томе.

### 4. `push-server` — Node.js Push Server

- **Назначение:** Контейнер с Node.js-приложением, реализующим push-сервер для отправки уведомлений.
- **Особенности:**
    - Собирается из собственного Dockerfile.
    - Использует `.env` файл для конфигурации.
    - Взаимодействует с Redis и приложением через отдельные сети.

## Схематичное представление архитектуры

- `app` ↔ `mysql` (через сеть `mysql-net`)
- `app` ↔ `push-server` (через сеть `app-net`)
- `push-server` ↔ `redis` (через сеть `push-net`)
